# Git Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `Sessions | Git` mode switch and a full-window git client per project (history, local changes, branches, merge/rebase, remote, stash) with agents for conflicts and quick `✦` actions.

**Architecture:** Reads stay on `git2` in `services/git.rs`; every write goes through the system `git` CLI via a shared runner extracted from `services/gh/checkout.rs` (ADR-0089). The renderer adds a mode store, a two-row top bar, a Git tab strip mirroring the session strip, and a `components/gitmode/` view that reuses the F18 graph pieces and `DiffView`. Agent work uses the existing session launch path (`startSession` + `setLaunch({prompt})`) and a new one-shot `claude -p` runner.

**Tech Stack:** Rust (tauri 2, git2 0.21, tokio, tempfile), React + TypeScript, zustand, TanStack Query/Router, dnd-kit, vitest, Playwright smoke.

**Spec:** `specs/05-features.md` § F35 and `specs/adr/0089-git-mode-writes-through-the-git-cli.md`.

## Global Constraints

- Writes: system `git` CLI only, argv (never a shell), `-C <dir>`, `GIT_TERMINAL_PROMPT=0`, kill-on-drop, timeouts (network ops 120 s, local ops 60 s). `git2` stays read-only and transport-free.
- Every op result carries the exact command line it ran; failures show git's stderr unedited.
- Never add `Co-Authored-By` or any attribution trailer.
- Agents start only from a click. Conflicts: banner with `✦ Resolve with agent`, never auto-start.
- Destructive ops confirm every time: discard (file/hunk), delete branch, stash drop, abort merge/rebase, undo rebase.
- Not in v1: force push, per-block conflict choices, cherry-pick/revert/reset menu items, tags, blame, worktree actions. Never: interactive rebase.
- Chrome heights: tools row `h-10.5`, work row `h-9`, session tab `h-7.5` (unchanged). Update `DESIGN.md` in the same commit as the visual change.
- Frontend rules (`.claude/rules/frontend.md`): `IconButton` for icon-only controls, dnd-kit not HTML5 DnD, one-line `title`s, `@factorai/ui` menus.
- Every new Tauri command gets a `mockInvoke` case in `apps/desktop/src/lib/tauri.ts` (unknown names throw).
- Quick `✦` actions in this iteration run Claude only (`claude -p`); for a Codex project they are hidden. *Deviation from F35 (`codex exec`), recorded in the spec in Task 9.*

## Review Focus

1. A path or branch name starting with `-` (e.g. a file named `-rf`) must never be read as an option → every pathspec goes after `--`, branch names validated (`validate_ref_name`). Test in Task 1.
2. An agent-proposed command with a shell metachar, `-c`, `--exec`, `reset --hard`, `push --force` must be refused → Task 2 tests.
3. Pressing a write button while another write is running (double click) must not start a second git → one in-flight op per repo, button disabled; Task 5 test.
4. Git mode on a project that is not a git repository / has no commits / detached HEAD must render a clear state, not crash → Task 3 + Task 5 tests.
5. `git` missing on PATH: history still works, write buttons show "git not found on PATH" → Task 1 (error kind) + Task 5 smoke.

**Interfaces:**
- Produces (Rust, serde camelCase, tag `"kind"`):
  ```rust
  pub enum GitOp {
    Stage { paths: Vec<String> }, Unstage { paths: Vec<String> }, Discard { paths: Vec<String> },
    ApplyPatch { patch: String, cached: bool, reverse: bool },   // hunk stage/unstage/discard
    Commit { message: String, amend: bool },
    Checkout { branch: String }, CreateBranch { name: String, at: String, checkout: bool },
    RenameBranch { from: String, to: String }, DeleteBranch { name: String },
    Merge { branch: String }, Rebase { onto: String },
    MergeAbort, RebaseAbort, RebaseContinue, ResetHardTo { sha: String }, // ResetHardTo only for Undo rebase
    CheckoutSide { path: String, theirs: bool },                // + git add
    Fetch, Pull, Push { set_upstream: bool },
    StashPush { message: Option<String> }, StashApply { index: usize }, StashPop { index: usize }, StashDrop { index: usize },
  }
  pub struct GitOpResult { pub command: String, pub ok: bool, pub stdout: String, pub stderr: String }
  pub fn args_for(op: &GitOp) -> AppResult<Vec<String>>      // pure; validates names
  pub fn validate_ref_name(name: &str) -> AppResult<()>       // rejects leading '-', whitespace, "..", control chars, empty
  pub async fn run_op(dir: &str, op: GitOp) -> AppResult<GitOpResult>
  ```
  Command: `git_op(project_path: String, op: GitOp) -> AppResult<GitOpResult>`; TS `cmd.gitOp(projectPath, op)`.
- Commit uses `commit -F -` with the message on stdin (no trailer added); an empty message means `commit --no-edit` (concluding a merge with git's prepared message). Push with `set_upstream` → `push -u origin HEAD`. Merge → `merge --no-edit <branch>` (fast-forward allowed). Rebase → `rebase <onto>`. A non-zero exit returns `Ok(GitOpResult{ok:false,..})` (conflicts are a state, not an error); spawn/timeout/not-found return `Err`.
